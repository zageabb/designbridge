# v0.3 Conversational Design Operations

DesignBridge v0.3 introduces a structured edit layer between the AI and the canonical design document.

## Operation language

Supported operations:

- `update_node`
- `add_node`
- `remove_node`
- `move_node`
- `set_color_token`
- `set_spacing_token`

Each operation is validated before application. The complete resulting DesignBridge document is revalidated after the batch, so broken component references, duplicate IDs and other schema violations fail rather than being persisted.

## Conversation flow

```text
User instruction
      |
      v
Ollama design proposer
      |
      v
OperationBatch JSON
      |
      v
Pydantic validation
      |
      v
Deterministic dry-run
      |
      +--> structured before/after changes
      +--> preview document
      |
      v
User accepts proposal
      |
      v
Canonical DesignBridge JSON
```

The model does not edit the document directly. It only proposes operations.

## API

### POST /api/operations/apply

Applies an explicit operation batch to a document.

### POST /api/operations/propose

Inputs:

- `document`
- `instruction`
- optional `ollama_url`
- optional `model`

The endpoint asks Ollama for an operation batch and dry-runs it through the same deterministic engine before returning both the batch and preview.

## Local configuration

```bash
export DESIGNBRIDGE_OLLAMA_URL=http://192.168.1.249:11434
export DESIGNBRIDGE_OLLAMA_MODEL=qwen3:14b
```

The browser UI now includes an **AI design change** box. Proposed operations are shown before acceptance and the visual preview renders the proposed document.
