# v0.11 Selective Penpot pull

DesignBridge v0.11 lets users apply selected safe node changes from a newer DesignBridge revision without pulling every outstanding change into Penpot.

## Supported selective pull

Selective pull is limited to existing nodes with non-structural property changes.

Examples:

- text
- name
- x/y
- width/height
- direct fill
- supported flex layout properties

## Not selectively pulled

The following still require a full pull:

- added nodes
- removed nodes
- scope/reparenting changes
- token changes
- structural component changes

## Revision safety

A selective pull does **not** automatically mark Penpot as fully synchronized.

The stored Penpot revision advances only when:

1. every outstanding safe changed node is selected; and
2. there are no unsupported structural or token changes outstanding.

If only some nodes are pulled, the chosen Penpot shapes are updated but Penpot remains marked behind the current DesignBridge revision.

## API

`POST /api/penpot/projects/{project_id}/selective-pull`

Example request:

```json
{
  "from_revision": 4,
  "node_ids": ["title", "kpi-row"]
}
```

The response includes:

- selected node snapshots;
- remaining changed node IDs;
- source and target revisions;
- the complete canonical diff;
- `can_advance_revision`.

## Penpot UI

The revision-diff panel now presents checkboxes for selectively pullable changed nodes and a **Pull selected changes** action.

Only the selected linked Penpot shapes are updated.

## Next milestone

The next useful slice is richer property-level selection and review:

- choose individual properties rather than whole nodes;
- identify local Penpot edits that would be overwritten;
- show a three-way comparison between the Penpot base revision, current Penpot state, and latest DesignBridge state.
