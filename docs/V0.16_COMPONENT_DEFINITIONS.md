# v0.16 Component definition synchronization

DesignBridge v0.16 adds safe synchronization for Penpot component main definitions.

## Principle

A component definition and an instance override are different layers of state.

DesignBridge now treats them separately:

- **component definition** — the Penpot main component and its main members;
- **instance override** — per-copy deviations already stored on the canonical instance node.

Updating a definition must not erase instance-specific values.

Penpot itself propagates main-component changes to copies while preserving touched/overridden properties, so DesignBridge targets only the main definition and lets Penpot retain native inheritance behavior.

## Safe component definition properties

Definition capture is intentionally limited to:

- name;
- text;
- direct fill when the canonical node is not token-bound.

Structural edits remain unsupported in this milestone.

## Definition report

`POST /api/penpot/projects/{project_id}/component-definitions`

The report identifies for each canonical component:

- in-sync definitions;
- changed main definitions;
- missing Penpot mains;
- root property changes;
- changed component children;
- existing instance overrides that must remain protected.

## Capture Penpot definition changes

`POST /api/penpot/projects/{project_id}/capture-component-definitions`

The capture operation:

1. requires a matching DesignBridge revision;
2. accepts explicit component IDs;
3. rejects components whose main definition is missing;
4. converts safe main changes into deterministic `update_node` operations;
5. validates the resulting canonical document;
6. saves a new revision only when something changed;
7. leaves all instance override maps unchanged.

## Apply DesignBridge definitions to Penpot

The Penpot plugin can also apply the canonical DesignBridge component definition back to Penpot.

It updates only:

- component main roots;
- component main members.

It never writes directly to component copy members.

Penpot then handles inheritance to component copies using its native component synchronization behavior.

## Revision safety

Applying only component definitions from a newer DesignBridge revision is a partial reconciliation.

If Penpot is based on an older revision, DesignBridge does **not** advance the stored Penpot revision merely because component definitions were applied. Other outstanding document changes must still be reconciled.

## Penpot UI

The plugin now includes **Review definitions**.

For changed components it offers:

- **Capture Penpot definitions** — save safe main edits into DesignBridge;
- **Use DesignBridge definitions** — apply canonical main values back to Penpot.

The review also shows how many protected instance override properties exist beneath each component.

## Not included yet

This milestone does not automatically synchronize:

- child add/remove;
- hierarchy changes;
- reparenting;
- layout structure;
- token-bound fill changes;
- variant structure;
- component swaps.

These remain explicit unsupported or review-only cases.

## Next milestone

The next useful slice is component variants and variant-safe instance switching:

- represent variants canonically;
- map Penpot variant components;
- preserve compatible overrides across variant changes;
- surface incompatible override/property mappings before a switch.
