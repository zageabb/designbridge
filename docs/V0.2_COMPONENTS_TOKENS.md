# v0.2 Components and Tokens

This slice strengthens the canonical model and Penpot handoff.

## Added

- typed color, spacing and radius token containers;
- `fill_token` references on design nodes;
- validation that instance references resolve to declared components;
- validation that portable node IDs are unique across components and pages;
- browser preview support for flex layout, token fills and component instances;
- Penpot Design System page generation;
- native Penpot library components and component instances;
- Penpot local color-library entries for DesignBridge color tokens.

## Penpot mapping notes

Penpot's plugin API exposes local library components and component instances. DesignBridge creates each declared component on a dedicated **Design System** page, registers it with `penpot.library.local.createComponent(...)`, and uses `component.instance()` for page instances.

Color tokens are currently represented both in canonical DesignBridge tokens and as Penpot local library colors. Penpot's newer Design Tokens system follows the W3C DTCG direction; direct token-catalog binding will be added once the adapter semantics are stable.

## Acceptance for this slice

A DesignBridge JSON document containing a reusable KPI card should:

1. validate;
2. render its layout and instances in the local preview;
3. import a real main component into Penpot;
4. create linked instances on the target design page;
5. retain DesignBridge IDs for future round-trip updates.
