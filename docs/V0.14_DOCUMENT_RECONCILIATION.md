# v0.14 Whole-document Penpot reconciliation

DesignBridge v0.14 expands synchronization review from the active Penpot page to the whole file.

## Whole-file snapshot

The Penpot plugin now inspects every page in the current file and collects every shape carrying a DesignBridge link.

It does this without changing the active page.

Each snapshot records:

- Penpot page ID and name;
- canonical DesignBridge page ID when available;
- linked DesignBridge node ID;
- supported semantic properties used by three-way review.

## Page identity

Newly imported DesignBridge pages are tagged with:

`designbridge:page-id`

The Design System page uses the reserved ID:

`__components__`

This gives reconciliation a stable mapping between canonical DesignBridge pages and Penpot pages.

Existing Penpot files without the tag fall back to page-name matching.

## Reconciliation report

The new document reconciliation engine reports:

- expected canonical nodes;
- linked nodes found in Penpot;
- missing linked nodes;
- unknown DesignBridge IDs found in Penpot;
- duplicate DesignBridge links;
- per-page expected/linked counts;
- per-page coverage percentage;
- page-location mismatches;
- document-wide three-way conflict counts.

## API

`POST /api/penpot/projects/{project_id}/document-reconciliation`

Example request:

```json
{
  "from_revision": 6,
  "snapshots": [
    {
      "designbridge_id": "title",
      "designbridge_page_id": "dashboard",
      "page_id": "penpot-page-uuid",
      "page_name": "Dashboard",
      "text": "Current Penpot text"
    }
  ]
}
```

## Penpot UI

The direct-sync panel now includes **Review whole document**.

The report shows:

- overall linked coverage;
- incomplete page count;
- per-page linked/expected totals;
- missing node IDs;
- unknown links;
- duplicate links;
- document-wide conflict/local-only/remote-only counts.

## Cross-page property updates

Property-level resolutions can now apply narrow updates to linked shapes on any page in the file, not only the currently active page.

## Safety

Whole-document review is non-destructive.

No page is switched and no shape is changed during reconciliation.

## Next milestone

The next useful slice is component/instance semantics:

- identify canonical component definitions and Penpot component instances;
- distinguish component-definition changes from instance overrides;
- synchronize safe overrides without flattening component relationships;
- surface unsupported override conflicts explicitly.
