# v0.12 Three-way Penpot review

DesignBridge v0.12 adds three-way comparison between the Penpot base revision, the current Penpot canvas state, and the latest DesignBridge revision.

## Why this exists

A revision diff can show that DesignBridge changed, but it cannot tell whether the Penpot user has independently edited the same property since the last synchronization.

Three-way review detects that condition before a pull overwrites local Penpot work.

## Inputs

For each linked shape on the current Penpot page, DesignBridge compares:

1. **Base** — the canonical DesignBridge node at Penpot's stored revision.
2. **Local** — the current Penpot shape snapshot.
3. **Latest** — the current canonical DesignBridge node.

## Property classifications

Each reviewed property is classified as:

- `remote_only` — changed in DesignBridge only;
- `local_only` — changed in Penpot only;
- `same_change` — both changed to the same value;
- `conflict` — both changed the property differently.

A conflict is the case most likely to overwrite meaningful local work.

## Supported properties

Three-way review currently covers the same safe semantic properties used by direct sync:

- name
- x / y when represented canonically
- width / height when represented canonically
- text
- direct fill when not token-bound
- supported flex layout values

## API

`POST /api/penpot/projects/{project_id}/three-way-review`

Example:

```json
{
  "from_revision": 4,
  "snapshots": [
    {
      "designbridge_id": "title",
      "type": "text",
      "text": "Locally edited title"
    }
  ]
}
```

The response includes a node-by-node property breakdown with base, local and latest values and a summary count by classification.

## Penpot UI

The plugin now includes **Check local conflicts**.

It snapshots all DesignBridge-linked shapes on the current page and shows:

- true conflicting properties;
- local-only Penpot edits;
- base/local/latest values for conflicts.

No shape is changed by the review.

## Safety

This feature is informational and non-destructive.

Existing full and selective pull paths still require an explicit user action.

## Next milestone

The next useful slice is property-level pull resolution:

- choose individual remote-only properties;
- explicitly resolve conflict properties as Keep Penpot or Use DesignBridge;
- apply only the chosen properties;
- preserve revision safety until every outstanding difference is reconciled.
