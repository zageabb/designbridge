# v0.8 Conflict-aware Penpot sync

DesignBridge v0.8 prevents stale Penpot edits from overwriting newer DesignBridge revisions.

## Revision tracking

The Penpot plugin stores the last synchronized DesignBridge revision in file plugin data:

- `designbridge:document-id`
- `designbridge:revision`

The plugin displays the local revision alongside the current DesignBridge revision.

## Sync states

The direct-sync status endpoint reports:

- `in_sync`
- `behind`
- `ahead`
- `unknown`

## Conflict protection

Penpot pushes now include `expected_revision`.

DesignBridge compares that value with the project's current revision before applying any reverse operations.

If the revisions differ, the API returns HTTP 409 with:

```json
{
  "code": "revision_conflict",
  "message": "Penpot is based on an older DesignBridge revision",
  "expected_revision": 3,
  "current_revision": 4
}
```

No Penpot changes are applied and no new revision is created.

The plugin tells the user to pull the latest DesignBridge revision before attempting another push.

## Pull behavior

A successful pull:

1. fetches the latest canonical DesignBridge revision;
2. updates linked Penpot shapes in place;
3. records the pulled revision in Penpot file metadata;
4. marks the connection as `in_sync`.

## Push behavior

A successful push:

1. sends selected linked Penpot snapshots plus `expected_revision`;
2. performs deterministic reverse comparison;
3. validates the resulting DesignBridge document;
4. saves a new revision;
5. stores the new revision in Penpot metadata;
6. returns to `in_sync`.

## Next milestone

The next slice should introduce revision-aware automatic refresh:

- lightweight periodic status check;
- passive "new DesignBridge revision available" indicator;
- optional one-click review/pull;
- no automatic overwrite of Penpot content.
