# v0.10 Reviewable revision diffs

DesignBridge v0.10 adds canonical revision comparison so users can see exactly what changed before pulling a newer revision into Penpot.

## Canonical diff

The new revision comparison works on DesignBridge documents rather than visual screenshots.

It reports:

- added node IDs;
- removed node IDs;
- changed node IDs;
- changed properties on each node;
- node scope changes;
- changed token sections.

Child arrays are intentionally excluded from raw property comparison so structural additions/removals are reported as node-level changes instead of unreadable nested JSON blobs.

## API

`GET /api/penpot/projects/{project_id}/diff?from_revision=N`

By default, the endpoint compares the specified revision with the project's current revision.

An optional `to_revision` can compare two specific historical revisions.

## Penpot review workflow

When the plugin detects that Penpot is behind DesignBridge:

1. the update-available badge appears;
2. the plugin retrieves a revision diff;
3. the user can see changed node IDs and properties;
4. **Review latest** loads the newest JSON for inspection without changing the canvas;
5. **Pull latest** remains the explicit action that updates Penpot.

## Safety

Revision diffs are informational only.

They do not bypass conflict protection and they never modify Penpot automatically.

## Next milestone

The next useful slice is selective pull for supported non-structural changes:

- choose individual changed node IDs;
- fetch the latest canonical values for those nodes;
- update only those linked Penpot shapes;
- advance the stored revision only when the selected pull is reconciled safely.
