# v0.15 Component and instance semantics

DesignBridge v0.15 adds explicit component-instance awareness to the Penpot synchronization layer.

## Native Penpot relationships

The plugin now uses Penpot's component APIs to distinguish:

- component main roots;
- component main members;
- component copy roots;
- component copy members;
- detached/basic shapes.

It also records the linked Penpot library component and the owning DesignBridge instance root.

## Canonical instance overrides

Instance nodes now support a safe `overrides` map keyed by canonical component child ID.

Supported override properties are intentionally limited to:

- text
- name
- direct fill

Example:

```json
{
  "id": "card-instance",
  "type": "instance",
  "component_id": "card",
  "name": "Card instance",
  "overrides": {
    "card-label": {
      "text": "Supplier risk"
    }
  }
}
```

Non-instance nodes cannot define overrides, and unsupported override properties are rejected by validation.

## Component integrity report

`POST /api/penpot/projects/{project_id}/component-report`

The report identifies:

- correctly linked instances;
- missing instances;
- detached instances;
- swapped component references;
- duplicate instance roots;
- safe override differences between Penpot and DesignBridge.

## Safe override capture

`POST /api/penpot/projects/{project_id}/capture-instance-overrides`

The operation:

1. requires the Penpot revision to match the current DesignBridge revision;
2. accepts explicit instance IDs;
3. rejects missing, detached, or otherwise invalid instances;
4. captures only safe overrides;
5. writes a new canonical revision only when the override set actually changed.

## Penpot UI

The plugin now includes **Review components**.

When safe overrides differ, the user can choose **Capture safe overrides** to persist them into DesignBridge.

## Reapplying overrides

Canonical overrides are applied back into Penpot when:

- an instance is initially created from a DesignBridge document;
- a linked instance is updated from a later DesignBridge revision.

This keeps the canonical model and rendered Penpot instance consistent.

## Duplicate-link correction

Component copy members may carry the same canonical source child IDs as their main component definition.

Whole-document reconciliation now excludes copy members from standalone node coverage and duplicate-link checks. Their values are analyzed as instance overrides instead.

## Next milestone

The next useful slice is component definition synchronization:

- safely detect changes to component main definitions;
- distinguish definition edits from per-instance overrides;
- propagate compatible definition changes while preserving instance overrides;
- surface incompatible changes before applying them.
